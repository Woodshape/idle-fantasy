Current Combat Implementation

Combat Main Loop Plan

Combat now runs from one authoritative simulation tick. Movement and the wider idle loop can keep their normal updates, but combat decisions, cooldowns, action order, hit rolls, damage, death, and combat state snapshots happen on discrete ticks.

The current implementation is a one-adventurer versus one-monster encounter using shared combat actions, tick counters, bridge events, and deterministic action priority.

0.25s Simulation tick interval owned by GameController.
1v1 Current encounter shape: one adventurer against one monster.
3 + 1 Adventurer has heavy_strike, spark, and basic_attack; monster has basic_attack.
Ticks Basic attack, skill cooldown, global cooldown, cast, and recovery are integer counters.

Current Architecture

Where Responsibilities Live

GameController

Owns the 0.25 second simulation clock, increments SimulationTickCount, emits simulation_tick, and calls the active combat controller.

AdventurerController

Runs the high-level idle loop: choose target, travel, start combat, collect loot, return to town, recover, and repeat.

AdventurerCombatController

Owns the active 1v1 encounter, creates runners, processes combat ticks, rolls action order, handles end conditions, and publishes encounter state.

CombatActionRunner

Owns one combatant's state, target, queued action, active action, cooldowns, casts, recovery, action selection, hit rolls, damage, and snapshots.

CombatAction

Describes action data: id, kind, range, cooldown, cast, recovery, target requirement, movement flag, order weight, damage multiplier, and basic cooldown use.

ICombatant

Shared surface for Adventurer and Monster: stats, identity, alive state, damage application, combat snapshots, and bridge state.

Important Shape

There is no standalone CombatEncounter, CombatDecisionController, CombatTickResolver, or cooldown object yet. Those responsibilities are currently folded into AdventurerCombatController and CombatActionRunner.

Tick Flow

No Attacks Between Ticks
Clock GameController accumulates 0.25 seconds and emits simulation_tick.
Start The active encounter emits combat_tick_started.
Counters Runners decrement cooldown, cast, recovery, and skill counters.
Queue Ready runners choose the first available action and enter Queued.
Resolve Actions roll order, resolve damage, handle death, publish state, and emit combat_tick_completed.

Game Tick Responsibilities

  1. Accumulate physics delta.
  2. Increment SimulationTickCount.
  3. Emit simulation_tick.
  4. Call ProcessSimulationTick.
  5. Publish simulation_clock.

Encounter Tick Responsibilities

  1. Advance runner counters.
  2. Queue ready actions.
  3. Roll action order.
  4. Resolve queued actions.
  5. Handle death or defeat.
  6. Publish combat_encounter.

Action Priority

The adventurer scans actions in list order, so heavy_strike is preferred whenever ready, then spark, then basic_attack. Monsters currently only have basic_attack.

Attack Speed Meaning

AttackSpeed currently means basic attack cooldown ticks, not attacks per second. Basic cooldown is max(1, owner.AttackSpeed).

Resolution Rules

Rolls And Formulas

Action Order

initiative_score =
  random(1, 100)
  + initiative
  + max(0, 12 - max(1, attack_speed_ticks))
  - action_weight

Hit Chance

hit_chance =
  clamp(
	    0.5 + clamp(attacker_accuracy - defender_evasion, 0, 1),
    0.05,
    0.95
  )

Damage

damage =
  hit
    ? max(1, round(attack * multiplier) - defense)
    : 0

Tie Breakers And Cancellation

Actions sort by higher score, higher initiative, lower AttackSpeed tick value, then stable CombatantId. The runner enforces Range before selection, queueing, and resolution. The opening distance is derived from the longest adventurer action range, which currently means spark range and keeps melee out of range. Mira stops moving while casting. When spark resolves and hits, the affected monster aggros onto the adventurer and moves to attack distance. Monsters can also aggro when an adventurer enters AggroRange. Social aggro is backlog.

Accuracy/Evasion Options

symmetric_linear =
  clamp(0.5 + accuracy - evasion, 0.05, 0.95)

scaled_symmetric =
  clamp(0.5 + 0.5 * clamp(accuracy - evasion, -1, 1), 0.05, 0.95)

diminishing_returns =
  0.05 + 0.90 * accuracy / (accuracy + evasion + constant)

Acceptance Criteria

Definition Of Done
  • Combat actions resolve only on simulation ticks.
  • Adventurer and monster updates process once per combat tick.
  • Basic attacks and heavy_strike use integer tick counters.
  • spark uses a 12-tick cast plus integer skill cooldown and global cooldown counters.
  • The game does not run per-combatant per-frame action timers.
  • Basic attack cadence comes from AttackSpeed tick values.
  • At least one cooldown skill exists and matures through tick counters.
  • At least one spell casts and resolves through tick counters.
  • Action range is enforced before actions resolve.
  • Attacked monsters aggro onto the attacking adventurer and move into attack distance.
  • Same-tick actions use initiative/order resolution.
  • Dead targets cancel later queued actions.
  • Combat resolves death, rewards, return to town, recovery, respawn, and repeat loop.
  • Bridge events expose tick start, tick complete, queue, order roll, resolve, cooldown start, cooldown ready, cast start, cast complete, and simulation tick.
  • Bridge state exposes per-combatant tick counters.
  • Headless verification proves at least one full loop completes.
