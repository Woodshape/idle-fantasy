Independent Combat Timers

Combat Main Loop

Refactor combat from one paired attack tick into an entity-driven combat loop where every combatant owns its own action timing.

Adventurers, monsters, skills, casts, recoveries, and cooldowns should advance independently from the lower-frequency game simulation tick.

Core Change Remove paired adventurer attack plus immediate monster counterattack.
Timing Drive actions from per-combatant timers updated by frame or physics delta.
Simulation Use a separate low-frequency tick for AI hints, effects, regen, and aggregate state.
Proof Expose event timestamps and timers through TestBridge for headless verification.

Two Clocks

Design Decision

Simulation Tick

Low-frequency world and decision maintenance. Initial interval:

simulation_tick_interval = 0.25 seconds
  • AI target reconsideration when out of combat.
  • Buff and debuff duration cleanup.
  • Regeneration, damage-over-time, and healing-over-time pulses.
  • Encounter timeout checks.
  • Bridge state aggregation.

Combat Action Timers

Per-entity timers for moment-to-moment combat. These should run continuously while a combatant is active.

  • Basic attack cooldowns.
  • Skill cooldowns.
  • Cast time.
  • Recovery windows.

Simulation Tick Must Not

  • Trigger basic attack swings directly.
  • Pair adventurer and monster attacks.
  • Block cast completion until the next tick.
  • Delay skill cooldown readiness after its timer reaches zero.

Starting Point To Replace

  • AdventurerCombatController.ResolveCombatTick resolves both attacks.
  • CombatTickInterval = 1.0.
  • The adventurer attacks first and the monster immediately attacks back if alive.
  • Skill, casting, recovering, and disabled states currently exist only as enum values.

Initial States

  • OutOfCombatNo active encounter.
  • EngagingEntering combat and validating target or range.
  • ReadyCan evaluate and choose an available action, or wait if no action is currently available.
  • UsingActionResolving an instant action.
  • CastingCast time is counting down.
  • RecoveringShort post-action lockout.
  • DisabledUnable to act because of a condition.
  • DefeatedHealth is zero.

Cooldowns Are Not States

BasicAttackCooldownRemaining and SkillCooldowns are action availability timers. A combatant can stay Ready while one skill has 60 seconds left on cooldown, choose another available skill, make a basic attack if ready, or wait for the next relevant timer to mature.

Action Timing Model

Independent Cadence

Timer Types

  • Basic attack cooldown derives from the attacker's attack speed and gates only the next basic attack.
  • Skill cooldown starts when its skill is used and gates only that skill.
  • Cast time counts down after an action begins.
  • Recovery time optionally locks out the next action after resolution.

Cooldown timers are checked by the decision controller when selecting an action. They should not force CombatState to become AttackCooldown or SkillCooldown.

Initial Formula

basic_attack_interval = 1.0 / attacks_per_second
adventurer_attacks_per_second = 1.0
monster_attacks_per_second = 0.65

The adventurer and monster no longer exchange paired turns. Each attacks when its own timer is ready.

Action Flows

First Slice Behavior

Enter Combat

  1. Set CurrentTarget.
  2. Enter Engaging.
  3. Validate target is alive and in range.
  4. Enter Ready.
  5. Decision controller chooses an action.
  6. If basic attack is chosen and ready, resolve attack.
  7. Start basic attack cooldown from attack speed.
  8. Enter Recovering if needed, otherwise return to Ready.

Physics Update

  1. Reduce combat action timers by delta.
  2. Reduce cast and recovery timers by delta.
  3. Reduce skill cooldown timers by delta.
  4. If a cast completes, resolve the action.
  5. If the combatant is Ready, ask for the next available action.
  6. If the target died, clear action state and let encounter or intention logic resolve the outcome.

If all relevant cooldowns are still running, the combatant stays Ready and waits. The next decision pass can run when a cooldown-ready event fires, on the next physics frame, or through a lightweight scheduler.

One basic attack plus one simple cooldown skill is enough to prove the model.

Combat Decision Rules

Deterministic First

Adventurer Priority

  1. If dead, stop.
  2. If disabled, wait.
  3. If no valid target, exit combat.
  4. If a high-priority skill is ready and conditions match, use it.
  5. If basic attack is ready, basic attack.
  6. Otherwise wait until the next action timer matures.

Monster Priority

  1. If dead, stop.
  2. If disabled, wait.
  3. If no valid target, exit combat.
  4. If basic attack is ready, basic attack.
  5. Otherwise wait.

Implementation Steps

Build Order
  1. Add shared combat action types: CombatAction.cs, CombatActionKind, and basic attack construction.
  2. Add a shared combatant contract through ICombatant or CombatantComponent, then adapt Adventurer and Monster.
  3. Add a per-combatant action runner that tracks cooldowns, cast time, recovery time, skill cooldowns, and disabled state from physics delta.
  4. Give monsters their own combat controller or attach the same reusable CombatActionRunner.
  5. Replace paired ResolveCombatTick with independent action resolution.
  6. Add a simulation clock that emits simulation_tick and only handles low-frequency work.
  7. Add one simple adventurer skill such as heavy_strike on its own cooldown.
  8. Add an optional cast action and verify cast start, countdown, completion, and effect application.
  9. Update HUD and TestBridge state to show current action, combat state, cooldowns, cast remaining, recovery remaining, and encounter state.
  10. Build the project and run a headless TestBridge session to confirm independent timing through event timestamps.

Acceptance Criteria

Definition Of Done
  • Adventurer and monster attacks are not paired turns.
  • Adventurer and monster each own independent action timers.
  • Basic attack speed affects attack cadence.
  • At least one cooldown skill exists and matures independently from basic attack timing.
  • Optional cast action, if implemented, starts and completes from a cast timer rather than a simulation tick.
  • Simulation tick exists and is visibly separate from combat action timers.
  • Simulation tick does not directly trigger basic attacks.
  • Combat still resolves death, rewards, return to town, recovery, and repeat loop.
  • TestBridge events expose action start, action resolve, cooldown start, cooldown ready, and simulation tick.
  • Bridge state exposes per-combatant timers.
  • Headless verification proves at least one full loop completes.

Risks And Constraints

Keep It Focused

Avoid

  • Do not turn the action system into a full RPG rules engine yet.
  • Do not duplicate adventurer-only logic into monster-only logic.
  • Do not add parties, equipment, inventory, or shops in this slice.

Protect

  • Prefer shared action runner behavior.
  • Keep formulas explicit and logged.
  • Keep bridge events precise enough to debug timing bugs.
  • Preserve the current simple visible arena.

Resolved Decisions

Locked For This Slice
Attack Speed Store attack speed as attacks per second.
Global Cooldown Do not add a global cooldown in this slice.
Action Lists Do not make monsters use the same action list format as adventurers yet.
Effects Buffs and debuffs tick on the game simulation tick as fixed pulses for now.
Regeneration Regeneration also ticks on the game simulation tick.
