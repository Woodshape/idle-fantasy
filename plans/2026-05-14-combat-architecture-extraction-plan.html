Refactor Plan

Combat Architecture Extraction

This plan defines the future split between the existing AdventurerCombatController and CombatActionRunner, plus the planned CombatEncounter, CombatDecisionController, and CombatTickResolver.

The goal is to keep combat behavior stable while moving encounter ownership, action choice, and tick resolution into clearer units as multi-combatant fights become more important.

Adapter AdventurerCombatController stays Godot-facing and thin.
Executor CombatActionRunner keeps legal action lifecycle and counters.
Policy CombatDecisionController chooses action and target intent.
Tick CombatTickResolver resolves one authoritative combat tick.

Extraction Status

Plan Only

Keep Stable

  • Current bridge events.
  • Hit and damage formulas.
  • Tick-authoritative combat.
  • Existing full-loop verifier.

Extract Gradually

  • Decision policy first.
  • Tick resolution second.
  • Encounter ownership third.
  • Multi-combatant hardening after that.

Avoid In Same Change

  • Combat math rewrite.
  • Data-driven skill library.
  • Party reward splitting.
  • Broad framework migration.

Responsibility Matrix

Boundaries
Type Owns Should Not Own
AdventurerCombatController Godot integration, combat entry point, adventurer-facing state, result forwarding. Initiative resolution, action scoring, encounter membership, reward membership.
CombatActionRunner One combatant's counters, queued action, active action, range validation, resolve/cancel lifecycle. Encounter lifetime, party membership, high-level AI strategy, global action ordering.
CombatEncounter Encounter id, participants, dynamic joins, end conditions, reward membership, encounter state. Godot input, UI labels, action scoring formulas, low-level scene lookup.
CombatDecisionController Action and target intent from current state, archetype, range, cooldowns, health, and later tactics. Health mutation, counter decrementing, resolution events, node ownership.
CombatTickResolver Advance one tick, queue decisions, roll order, resolve or cancel actions, return tick results. Persistent encounter ownership, long-term AI, scene integration.

Current Classes After Split

Old Names

AdventurerCombatController

Becomes a thin adapter: it starts or joins combat for its parent adventurer, wires to the active encounter, publishes adventurer-facing state, and forwards combat end results to the idle loop.

  • Keep parent adventurer lookup.
  • Keep entry points used by AdventurerController.
  • Move participant lists and tick resolution out.

CombatActionRunner

Stays the legal executor for one combatant. It knows whether an action can execute and how to execute it, but no longer chooses the strategic action.

  • Keep counters, queued action, active action, range checks.
  • Keep action resolve/cancel and snapshots.
  • Move list-priority selection and target policy out.

New Extraction Targets

New Names

CombatEncounter

Owns the fight: participants, runners, dynamic joins, living counts, reward membership, end conditions, and encounter state.

CombatDecisionController

Chooses intent: action, target, and reason. Initial policies can preserve the current warrior, mage, and monster priorities.

CombatTickResolver

Owns one tick: counters, decisions, queueing, order rolls, resolution, cancellation, and tick result output.

Migration Plan

Low Risk Order
  1. Add passive records such as CombatDecision, CombatTickResult, and CombatEncounterState without changing behavior.
  2. Extract CombatDecisionController from runner action selection and controller target callbacks while preserving list-priority behavior.
  3. Extract CombatTickResolver from action queue collection, order rolling, and queued action resolution.
  4. Extract CombatEncounter from participant lists, runner lists, dynamic joins, end conditions, and encounter state.
  5. Harden multi-combatant behavior with dynamic join rewards, cross-encounter ownership checks, and 1v2 or 2v2 bridge verification.

Events And State

Compatibility

Preserve Events

  • combat_started
  • combat_tick_started / combat_tick_completed
  • combat_action_queued / combat_action_resolved
  • attack_roll_resolved / damage_applied
  • monster_joined_encounter, monster_defeated, adventurer_died

Preserve State

  • combat_encounter active flag and encounter id.
  • Participant arrays and living counts.
  • Per-combatant cooldown, cast, recovery, target, queued, and active action fields.
  • simulation_clock tick count and interval.

Acceptance Criteria

Definition Of Done

Refactor Gates

  • scripts/verify_combat_main_loop.sh still passes.
  • Existing bridge events remain available or intentional changes are documented.
  • AdventurerCombatController no longer owns tick resolution after resolver extraction.
  • CombatActionRunner no longer chooses strategic actions after decision extraction.

Combat Gates

  • CombatEncounter owns participants, dynamic joins, end conditions, and reward membership.
  • At least one 1v2 or 2v2 verifier covers multi-combatant behavior.
  • Dynamic joins cannot duplicate a monster across active encounters.
  • Reward membership includes monsters added after encounter start.
